# חיילים בלי מטווחים בתוקף — תצוגת מטווחים ודשבורד מפקד

## Goal

להציג למנהלי תורנויות ולמפקדים חיילים שאין להם כשירות מטווח תקפה, תוך הדגשה חזקה יותר כאשר לחייל יש תורנות עתידית הדורשת נשק ואין לו מטווח מתאים מתוזמן.

## Approved decisions

- לא יתווסף פריט ניווט חדש בשם `חוסר כשירות`.
- פריט הניווט הקיים `מטווחים` בתפריט תכנון יקבל badge אדום עם מספר החיילים הייחודיים ללא מטווח תקף, לפי היקף הצפייה של המשתמש.
- לחיצה על `מטווחים` תפתח את `RangesPage` ותציג בו את אזור חוסר הכשירות הנוסף.
- ב-`RangesPage` תתווסף תצוגת חיילים ללא מטווחים בתוקף, המחולקת לפי תתי-היררכיות ובדפוס של `PotentialPage`: שורות היררכיה מקוננות, ספירה, ושורות חיילים נפתחות.
- בדשבורד המפקד תתווסף חלונית קומפקטית של חיילים ללא מטווחים בתוקף. היא תכלול חיילים מהעץ הרקורסיבי של הצמתים שעליהם המפקד אחראי.
- מנהל תורנויות יראה בתצוגת המטווחים את כל החיילים שבתחומי ה-scope שלו; מנהל מערכת יראה את כולם. ההרשאה והסינון ייאכפו ב-backend.
- כל בדיקות ה"עתידי" מתחילות מהיום, כולל תורנויות עתידיות ומטווחים עתידיים.
- חייל ללא מטווח תקף יקבל אזהרה רגילה. אזהרה מודגשת תוצג כאשר קיימת לו תורנות עתידית מפורסמת הדורשת נשק ואין לו שיבוץ עתידי למטווח מתאים.

## Scope and data model

ה-backend יוסיף שירות קריאה משותף ושכבת API אחת לשתי התצוגות. השירות יחזיר חיילים ייחודיים, צומת היררכיה, הכשרות מטווח תקפות ותאריכי תפוגה, וכן את שדות האזהרה:

- `has_upcoming_weapon_duty`: קיימת תורנות מפורסמת מתאריך היום ואילך שדורשת סוג מטווח.
- `has_upcoming_matching_range`: קיים לחייל שיבוץ עתידי למטווח מתוכנן שסוגו מתאים לדרישת התורנות.
- פרטי התורנות והמטווח הרלוונטיים להצגה, כאשר קיימים.

החיילים נחשבים "בלי מטווחים בתוקף" כאשר אין להם הכשרת מטווח תקפה לתאריך היום. התאמה לתורנות נבדקת לפי `required_range_type` של סוג התורנות, באמצעות לוגיקת הכשירות הקיימת ולא באמצעות חישוב מקביל.

ה-count של ה-badge ייגזר מאותו read model או משאילתת count מקבילה לחלוטין, כך שלא ייווצר פער בין המספר בניווט לבין הרשימה.

## Authorization and scoping

- מפקד: שורשי scope הם הצמתים שהוא מפקד עליהם; כל צומת descendant נכלל.
- מנהל תורנויות: שורשי scope הם רשומות `DutyManagerScope`; כל descendant נכלל.
- מנהל מערכת: bypass מלא לכל הצמתים.
- חיילים ללא צומת לא ייכללו בתצוגות המנהל/מפקד.
- חייל שמופיע תחת צומת יחיד ייספר פעם אחת גם אם למשתמש יש scopes חופפים.

## Frontend behavior

### מטווחים

ב-`RangesPage` יתווסף אזור/טאב פנימי עבור חוסר הכשירות, בלי לשנות את טבלת אירועי המטווחים ואת פעולות הניהול הקיימות. הטבלה החדשה תשתמש ב-`DataTable`, `SoldierLink` ומיון ההיררכיה הקיים בפוטנציאל. לכל שורת היררכיה יוצגו מספר החיילים הלא-כשירים; פתיחת השורה תציג את החיילים, ההכשרות שלהם, ותורנות/מטווח עתידיים רלוונטיים.

הפריט הקיים `nav-ranges` יקבל את ה-badge האדום. אין להוסיף `nav-weapon-ineligible` או פריט מקביל.

### דשבורד מפקד

תתווסף חלונית `חיילים בלי מטווחים בתוקף` לרשימת הפאנלים הקיימת. החלונית תהיה קומפקטית ותציג שם, תת-היררכיה, הכשרות/תפוגה, וסימן אזהרה. חייל עם תורנות נשק עתידית וללא מטווח מתאים משובץ יקבל עיצוב אדום/מודגש וטקסט שמסביר את הדחיפות.

## Error handling and loading

- כשל בטעינת הנתונים יוצג במצב השגיאה המקובל של דפי המערכת, בלי להפיל את שאר דף המטווחים או הדשבורד.
- בזמן טעינה יוצגו מצב טעינה או מקפים, וה-badge יישאר מוסתר עד שמתקבל count תקף.
- אם אין חיילים מתאימים, יוצג empty state מפורש בעברית.

## Testing requirements

Backend:

- חישוב "מטווח תקף" לפי היום.
- זיהוי תורנות עתידית הדורשת נשק ומטווח מתאים משובץ.
- סינון רקורסיבי למפקד ולכל אחד מ-scopes של מנהל התורנויות.
- deduplication בחפיפת scopes.
- admin visibility ו-count התואם לרשימה.

Frontend:

- ה-badge מופיע על `nav-ranges` בלבד, עם count אדום, ואין פריט ניווט חדש.
- אזור חוסר הכשירות ב-`RangesPage` מציג היררכיה וחיילים ומדגיש את המצב הדחוף.
- חלונית הדשבורד מציגה scope נכון ומדגישה חייל עם תורנות נשק ללא מטווח מתאים.
- מצבי loading, empty ו-error.
