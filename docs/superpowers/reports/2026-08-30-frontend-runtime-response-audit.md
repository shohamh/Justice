# 2026-08-30 Frontend Runtime Response Audit

Scope: `frontend/src/api`, `frontend/src/hooks`, `frontend/src/pages`, and `frontend/src/components`.

Method: inventory runtime-shape risks where frontend state/render code consumes API or hook data without runtime validation, especially collection/object values later used with `map` / `filter` / `reduce` / `find` / `Object.*` or direct required-field access. Repeated consumer sites are grouped by the shared adapter seam that should be hardened first.

## Suggested hardening order

1. Shared paginated/list adapters used by multiple pages first: announcements, notifications, commander dashboard, scoring, soldiers, hierarchy.
2. High-fanout complex detail seams next: algorithm job payloads, range detail/edit payloads, calendar shift payloads, swap/request detail payloads.
3. Lower-severity object/count/settings endpoints after collection-crash seams are covered.
